# Rețetarul și rețetele în jurnal: plan de implementare

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/api/recipes` (CRUD cu arhivare, valori totale și per porție calculate la citire) și intrări de jurnal din rețete, în porții, cu snapshot.

**Architecture:** calculul valorilor stă în Domain (`Macros`, `RecipeNutrition`, funcții pure). `DiaryEntry` devine polimorfă (aliment sau rețetă), garantat de `CHECK`-uri în PostgreSQL. Application adaugă comenzile și interogările rețetarului după tiparul `Foods` și extinde handlerele jurnalului. WebApi expune `RecipesController`.

**Tech Stack:** .NET 8, EF Core 8 + Npgsql, MediatR 14, FluentValidation 12, xUnit + FluentAssertions + Moq, EF InMemory, Testcontainers (Podman).

**Spec:** `aplicatie/docs/specs/2026-10-16-recipes-design.md`. Secțiunile sunt referite ca §N, deciziile ca D1–D7.

## Global Constraints

- Comenzile `dotnet` rulează din `aplicatie/backend/`. Commit-urile se fac pe `feature/NUT-recipes`, în *Conventional Commits*, **fără `Co-Authored-By`**.
- Testele de integrare cer `export DOCKER_HOST=unix:///run/user/$(id -u)/podman/podman.sock TESTCONTAINERS_RYUK_DISABLED=true`.
- Tiparul Arrange-Act-Assert; numire `Method_Scenario_ExpectedResult`.
- Valori fixe (§3.4): nume 1–200 după trim; descriere ≤ 1000; instrucțiuni ≤ 10 000; `servingsCount` 1–50; `prepTimeMinutes` 0–1440; ingrediente 1–50, `foodId` distincte, `0 < quantityGrams ≤ 5000`; porții de rețetă în jurnal `0 < servings ≤ 50`.
- Rotunjire doar în DTO: `Math.Round(x, 1, MidpointRounding.AwayFromZero)`; `perServing` din totalul nerotunjit.
- Mesajele pentru utilizator sunt în română; codul în engleză. Enum-urile circulă ca text camelCase.
- Timpul curent vine doar din `IDateTimeProvider`.
- Fără `ExecuteUpdateAsync`/`ExecuteDeleteAsync` în Application (testele InMemory).
- Testele existente trebuie să rămână verzi; se modifică doar aserțiunile despre forma `DiaryEntryDto`.

## Review Focus

1. **Aliment arhivat după ce a intrat în rețetă:** `PUT` care păstrează ingredientul trece; `PUT` care adaugă un *alt* aliment arhivat dă 404. Testele `Update_KeepsArchivedIngredient_Succeeds` și `Update_AddsArchivedFood_ThrowsNotFound` sunt în Task 2.
2. **`PUT` pe o intrare-rețetă cu `quantityGrams`** (validatorul comun nu știe tipul intrării) → 400, nu salvare cu grame. Testul `Update_RecipeEntryWithGrams_ThrowsValidation` e în Task 4.
3. **Același aliment în `PUT` după `POST`:** reordonarea sau schimbarea cantității unui ingredient existent nu lovește indexul unic `(RecipeId, FoodItemId)`. Testul de integrare `Update_ChangesQuantityOfExistingIngredient_Returns200` e în Task 5 (pe Postgres real, unde indexul există).
4. **Rețeta altui utilizator în jurnal** (`recipeId` străin) → 404, nu intrare creată. Testul `Add_OtherUsersRecipe_ThrowsNotFound` e în Task 4.
5. **Ziua cu intrări mixte** (aliment + rețetă) adună corect totalurile și ordonează intrările după `CreatedAtUtc`. Testul `GetDay_MixedEntries_SumsBothKinds` e în Task 4.
